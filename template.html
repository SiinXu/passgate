templates/nextjs-webauthn/Runnable Next.js App Router example

A small Next.js app you can run locally and copy from: sign-up with a passkey, sign-in, a settings page to list and revoke keys, and recovery codes. Server code uses @simplewebauthn/server; the browser side uses @simplewebauthn/browser.

  • Route handlers for registration and authentication options + verification
  • Challenge store with expiry, plus a session cookie after login
  • Settings screen: list, rename, revoke passkeys
  • Recovery codes: generate, hash, show once, redeem
app/api/passkey/register/options/route.ts
import { generateRegistrationOptions } from "@simplewebauthn/server";

const options = await generateRegistrationOptions({
  rpName: "Acme",
  rpID: process.env.RP_ID!, // e.g. app.acme.com
  userName: user.email,
  excludeCredentials: user.passkeys.map((k) => ({ id: k.credentialId })),
  authenticatorSelection: { residentKey: "preferred", userVerification: "preferred" },
});
templates/supabase-migration/Password → passkey migration for Supabase

Steps for adding passkeys next to existing Supabase password accounts, so current users keep working while they enrol a passkey.

  1. Create the passkeys table with row-level security
  2. Offer "add a passkey" after a normal password login
  3. Let enrolled users sign in with a passkey first, password as fallback
  4. Optionally hide the password field once a user has two passkeys
migrations/001_passkeys.sql
create table public.passkeys (
  id           text primary key,  -- credential ID, base64url
  user_id      uuid not null references auth.users (id) on delete cascade,
  public_key   bytea not null,
  counter      bigint not null default 0,
  transports   text[],
  created_at   timestamptz not null default now()
);
alter table public.passkeys enable row level security;
templates/clerk-alternative-notes.mdKeep Clerk or move out: a decision note

If you already use Clerk, this note helps you decide whether to keep it and turn on its passkey option, or move auth into your own database.

Keep Clerk if

  • its built-in passkey option covers what you need
  • you rely on its user and organisation management UI

Move out if

  • you must own the credential table and session format
  • pricing per active user no longer fits your plan
clerk-alternative-notes.md
## Decision in one question
Do you need to own the credential table and the session format?
- No  → keep Clerk, turn on its passkey option, stop here.
- Yes → follow supabase-migration/ or the custom-JWT path.

We do not reverse-engineer or bypass Clerk.

FAQ

Do I need Next.js?

No. The example is Next.js, but the checklist, test plan and Supabase steps apply to any web stack that can run a WebAuthn server library.

Does it work with the Pages Router?

The example uses the App Router. The server logic is plain functions, so moving it into API routes is a small change.

Will the template be updated?

Every change is listed in the changelog below with its date.

Where does the interest form go?

Nowhere. It is saved in this browser's localStorage only. Nothing is sent to us, and it is not an order.

Is this a security audit?

No. PassGate is implementation help and a template. It does not certify your product. Responsibility boundaries are written into the order.
